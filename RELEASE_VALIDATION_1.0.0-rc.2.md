# Проверки 1.0.0-rc.2 — Build & Runtime Stabilization

База: предоставленный `CajeerBots-main.zip`, версия `1.0.0-rc.1`. Никакие существующие SQL migration files не изменены.

## Фактически выполнено в среде подготовки патча

- Node.js v22.16.0, TypeScript 5.8.3: реальная strict-компиляция пяти пакетов `core`, `deployment`, `docs`, `contracts`, `storage` с локально доступными типами Node.js.
- `node --test scripts/stabilization.test.mjs`: 5/5 тестов прошли, включая ожидание активного tick при shutdown, восстановление после периодической ошибки, отказ на первом tick, совпадение production env с конфигурацией runtime, безопасную генерацию `.env.production` без перезаписи.
- TypeScript parser: 284 исходных TS-файла проекта разобраны без синтаксических ошибок; это не полная проверка типов.
- JSON manifests, Compose YAML, CI YAML, OpenAPI YAML разбираются; граф 30 workspace-пакетов ацикличен.
- Статическое сопоставление: 102 модели Prisma, 102 SQL-таблицы в 21 существующей миграции, не обнаружено отсутствующих скалярных колонок по именам. Это не доказательство корректности исполнения SQL, типов, ограничений и drift.
- Сгенерированный `.env.production` проверен: права 0600, разные секреты, пароль DATABASE_URL совпадает с POSTGRES_PASSWORD.

## Блокеры допуска RC2

В среде подготовки отсутствуют pnpm, установленные зависимости проекта, PostgreSQL server и Docker. Запрос к registry.npmjs.org завершился ошибкой разрешения DNS; соединение по IP также не удалось. Поэтому **подлинный `pnpm-lock.yaml` не создан**. Прямые зависимости и версия pnpm закреплены; транзитивное разрешение должно быть зафиксировано штатным pnpm на машине с сетью. Docker и CI намеренно завершаются с ошибкой при отсутствии lockfile, а не выполняют неявное незакреплённое разрешение зависимостей.

Не выполнены и не считаются прошедшими: полный `pnpm install/build/typecheck/lint/test`, `prisma validate/generate/migrate deploy`, Supertest E2E, живой smoke API/bot/worker/CLI и Docker Compose. CI содержит эти проверки, но его зелёный статус должен быть получен реально. Проверки внешних Telegram/VK/Discord с реальными токенами, security tests и нагрузка остаются следующими этапами. Состояние: рабочие изменения исходников и частичная проверка; production допуск не выдан.

## Решения по стабилизации

- Node 22.16.0 выбран как доступный в среде и совместимый с исходной веткой. Перед GA необходимо подтвердить поддерживаемый актуальный LTS и обновить security-патчи Node и контейнеров; теги образов закреплены, но digest-пиннинг/SBOM не выполнены.
- `strict: true`, `noUncheckedIndexedAccess: true`, `noEmitOnError: true` сохранены. `exactOptionalPropertyTypes` и `noPropertyAccessFromIndexSignature` отключены: существующий код широко передаёт optional поля Prisma и читает JSON через свойства; эти дополнительные ограничения следует возвращать отдельно. ESLint использует базовый recommended TS набор с предупреждениями для legacy `any`/unused; typecheck остаётся отдельным обязательным шагом.
- Seed повторно не перезаписывает пользовательские значения и назначения прав существующим ролям; новые системные роли получают начальные permissions. Нет новой бизнес-миграции; добавлен стандартный migration_lock.toml.
- Публичная маршрутизация webhook через Nginx закрыта до проверки подлинности провайдеров в RC3. Внутренний сервер runtime остаётся для health и изолированных тестов.

## Как закрыть блокеры

В чистом checkout с сетью выполните команды из README: `pnpm deps:lock`, зафиксируйте настоящий lockfile, `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm typecheck`, `pnpm lint`, `pnpm prisma:validate`, `pnpm prisma:deploy`, `pnpm prisma:seed` дважды, unit/E2E/smoke, затем `docker compose ... up -d --wait`. Все команды должны завершиться успешно; исправьте реальные диагностические ошибки, если они обнаружатся. Не заменяйте typecheck транспиляцией без проверки типов и не помечайте релиз production-ready до успешного прогона.
