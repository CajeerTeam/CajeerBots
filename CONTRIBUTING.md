## Принципы разработки

1. Основной язык продукта, документации и пользовательских сообщений — русский.
2. Код пишется на TypeScript в строгом режиме.
3. Архитектура должна оставаться модульной и расширяемой.
4. Любая важная операция должна проектироваться с учётом RBAC, audit log, scopes, idempotency и rate limiting.
5. Расширения должны иметь manifest, permissions, semantic constraints и совместимость с engine API version.
6. Изменения API сначала отражаются в contract-first спецификациях.
7. Breaking changes допускаются только по SemVer и должны быть отражены в `CHANGELOG.md`.

## Рабочий процесс

1. Создайте отдельную ветку от актуальной основной ветки.
2. Опишите задачу, проблему или предложение до начала крупной реализации.
3. Вносите изменения небольшими логическими коммитами.
4. Для публичных API, CLI-команд, SDK и extension hooks обновляйте документацию.
5. Перед отправкой изменений запускайте проверки:

```bash
pnpm install
pnpm lint
pnpm test
pnpm build
```

6. Для изменений Prisma-схемы добавляйте миграции через Prisma Migrate.
7. Для изменений bot-runtime добавляйте unit-тесты и, где возможно, bot scenario E2E-тесты.

## Стиль кода

- TypeScript strict обязателен.
- Форматирование выполняется через Prettier.
- Линтинг выполняется через ESLint.
- Runtime-валидация публичных входных данных выполняется через Zod или утверждённые схемы.
- Логи пишутся структурированно через Pino.
- Ошибки должны быть типизированы и пригодны для диагностики.
